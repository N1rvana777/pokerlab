## 0. 本轮结论（2026-10-25 第二轮，逐条回答四个问题）

**(1) 实际 agent 的小规模整体策略误差是多少，与原来的混合对照有什么区别？**
- **测法**（§4.20）：在三个已有的极小参考游戏里，对每一手私牌都走 agent 自己的抽样、求解和查询路径，拼出 agent 实际会打的策略，再用精确最佳回应评估。每个设置测 3 个固定种子。
- **默认设置（150 次抽样）下的实际 agent**：

  | 参考游戏 | 实际 agent | 精确参考 | k=N 控制 |
  |---|---|---|---|
  | river 8 × 8，均匀 | 1.7–3.1% pot | ≤ 0.0006% | 0.0646% |
  | river 5 × 6，加权 | 0.36–0.85% | ≤ 0.0006% | 0.0070% |
  | turn + river 6 × 6（联合 agent） | 0.006–0.49% | ≤ 0.0006% | 0.0032% |

  - k=N 控制等于单次求解自身的误差，说明路径没有问题。
  - 这些极小 range 里每手都被抽到，所以误差来自抽样次数作权重带来的噪声。
  - 抽样次数少于手数时（k=4、8），实际 agent 的误差是 0.6–43%。
- **与混合对照的区别**：
  - 混合对照让未抽到的手牌用精确策略，所以它不是 agent 的行为。
  - 它有时比实际 agent 低很多（43.0% 对 14.0%），有时更高（4.8% 对 6.9%）。既不是上界或下界，也不是可相加的误差分量。
- **paired_flush 控制实例**（约 1,950 手）：在当前控制实例中，最近河牌排名映射是已确认的大误差来源；实际 agent 的采样及逐手重解误差尚未量化。
- **强制加入的本方手牌**：权重为 1，即一次抽样的权重。之后的决策一直沿用第一次求解的树，因为参考游戏里对手的动作都在树内，不会触发重解。

**(2) 新抽象在原参考游戏里的误差、耗时和内存，比旧映射改善多少？**

  |---|---|---|---|---|---|
  | paired_flush（调参） | 0.022 | 17.1 / 44.9 | 1.65 | 1.40 | **1.00** |

### 4.4 结果定义与验证范围（逐项回答）

**(1) Kuhn 为什么报告 17/18**
- **建模**：`subgame/instance.py:191` 的 `kuhn_instance()` 把 Kuhn 写成单街子博弈：双方各 1 前注，构成沉没底池 pot=2；之后只有一个 1 筹码的下注尺寸，不允许加注。
- **终局收益**：`subgame/cfr.py:68` 的 `terminal_values` 从前注之后起算，等于终局拿到的筹码（沉没底池 + 对手新投入）减去自己的新投入。因此 u0 + u1 = 2，先手均衡值 = 17/18。
- **换算成标准净收益**：再减去自己投入的前注 1（= pot/2），得到 17/18 − 1 = **−1/18**。报告字段 `value_net_of_equal_sunk_share` 直接给出这个值，测试中 DCFR 3,000 次后为 −0.0556。
- **常数偏移**：exploitability = (BR0 + BR1 − pot)/2（`cfr.py:301`）。零和口径下 BR'_p = BR_p − pot/2，所以 NashConv' = BR0 + BR1 − pot，与常数怎样在两人之间分配无关。测试 `test_kuhn_reports_net_value_and_offset_free_exploitability` 逐项核对。
- **复现**：`python -m pytest tests/test_plo_subgame.py -k kuhn -q`

**(2) 0.73% pot 怎么算**
- **指标**：exploitability = **NashConv/2**，NashConv = BR0 + BR1 − pot（`cfr.py` 的 `evaluate_profile`；定义写在报告的 `definitions` 字段里）。
- **分母**：子博弈起始底池 2,000 筹码（20bb），0.729% 即 14.585 筹码。
- **评估对象**：**平均策略**（`solver.average_profile()`）。最后一次迭代另报，同一运行为 1.14%（报告 `current_strategy`）。
- **最佳回应的动作集合**：只限该抽象树。这里是精简树：下注 1 pot、加注到 pot、无边界动作、最多 1 次加注。按信息集（己方手牌, 公共节点）取最优，对对手手牌求和并做卡牌移除。不覆盖树外尺寸。
- 只迭代 20 次，没有收敛，这是规模测试。

### 4.20 实际 agent 的小规模整体策略误差（`outputs/plo/v6/agent-reference/`，commit `62724b0`）

**做法**
- 对参考游戏里每一方的每一手私牌，都走一遍 agent 自己的代码路径：
  - `river_agent.sample_ranges` 抽样，种子是 [seed, hand_id=0, 玩家]，抽样结果与本方底牌无关；
  - 本方手牌没被抽到时，以权重 1（一次抽样的权重）加入；
  - 用 agent 的 spec 和求解函数求解，再按 agent 的方式查本方手牌的策略。
- 参考游戏里对手的动作都在树内，所以 agent 之后的决策一直沿用第一次求解的策略。这样拼出来的策略组合，就是 agent 实际会打的策略，然后在同一参考游戏里用精确最佳回应评估。
- **k=N 控制**：`range_samples=0` 表示不抽样，用全部参考手牌和它们的权重。这时每手私牌面对的都是同一个博弈，结果等于单次求解。
- **混合对照**（上一轮的"只换抽样"）：被抽到的手牌用共享抽样解，未抽到的手牌用精确参考策略。它不是 agent 的行为，这里只作比较。

**结果**（exploitability，% pot；每格是种子 1 / 2 / 3）

| 参考游戏（agent 设置） | 精确参考 | k=N 控制 | 实际 agent，默认 k=150 | 实际 agent，k=4 | 实际 agent，k=8 | 混合对照，k=4 | 混合对照，k=8 |
|---|---|---|---|---|---|---|---|
| river 8 × 8，均匀（`river_solver`，200 次） | 0.0006 | 0.0646 | 1.69 / 2.45 / 3.08 | 16.2 / 43.0 / 14.3 | 6.6 / 31.8 / 20.5 | 9.7 / 14.0 / 5.6 | 7.1 / 23.6 / 10.2 |
| river 5 × 6，加权、共用牌（`river_solver`，200 次） | 0.00005 | 0.0070 | 0.85 / 0.36 / 0.39 | 2.9 / 8.8 / 6.7 | 2.3 / 7.0 / 4.8 | 2.6 / 5.1 / 5.2 | 4.0 / 6.1 / 6.9 |
| turn + river 6 × 6（`turn_river_solver`，100 次） | 0.00003 | 0.0032 | 0.06 / 0.49 / 0.006 | 1.4 / 1.8 / 1.2 | 0.6 / 2.0 / 1.0 | 0.6 / 0.8 / 0.8 | 0.4 / 0.9 / 0.9 |

- **k=N 控制**等于单次求解自身的误差（0.0646%、0.0070%、0.0032%），说明拼装和评估的路径没有问题。
- **默认 k=150**：这些极小的 range 里，每手都被抽到了，没有发生强制加入（联合 agent 有 1 手例外）。误差全部来自抽样次数作权重带来的噪声：0.36–3.1%（river）和 0.006–0.49%（turn + river），而样本内的 exploitability 只有 0.005–0.08%。
- **抽样次数少于手数**（k=4、8）：实际 agent 的误差在 0.6%–43% 之间，随种子变化很大。
- **与混合对照的区别**：
  - 混合对照可以比实际 agent 低很多（river 8 × 8，k=4，种子 2：43.0% 对 14.0%），也可以更高（river 5 × 6，k=8，种子 3：4.8% 对 6.9%）。
  - 所以它既不是实际 agent 误差的下界，也不是上界，更不是可相加的误差分量。
- **结论范围**：只代表这三个极小参考游戏和这几个种子。paired_flush 那类约 1,950 手实例上，实际 agent 的误差仍未量化，完整评测约需 3,600 次求解。

### 4.22 四街蓝图 v0（`outputs/plo/v6/blueprint-*`）

**博弈与抽象**（详见 ARCHITECTURE 与 D25）
- 动作：20bb；翻前加注到 pot，最多 2 次加注，大盲有 limp 后的选择权；翻后 1/2 与 1 pot，加注 1 pot，每街最多 1 次加注，含 all-in 边界。
- 规模：18 棵街树，决策节点依次为 6 / 28 / 52 / 66（翻前 / 翻牌 / turn / river）。
- 抽象：翻前 16 档；翻牌和 turn 各 32 档（棋面相对强度 8 档 × 同花听牌 × 坚果同花阻断）；river 24 档。每街独立计算，不保持 perfect recall。

**正确性验证**（`blueprint-validate`，commit `884cb12`）
- 用 identity bucket 时就是精确信息集上的 ES-MCCFR。训练出的表映射到全宽求解器的同一节点编号，用精确最佳回应评估。

## 6. 已知问题与限制

1. **实际 agent 的误差**：只在极小参考游戏上测过（§4.20）。约 1,950 手实例上还没量化。抽样次数作权重本身就会带来 0.4–3% 的误差。
2. **turn 抽象**：v1 的 turn 特征不如只按胜率（0.35% 对 0.30%），需要重新设计。
3. **蓝图**：
   - 粗抽象、不保持 perfect recall，训练也未收敛（变化量约 0.09），全游戏 exploitability 不可计算。
   - 在一条行动线上，蓝图的 turn/river 策略离局部均衡 6.07% pot。
   - 对局中 3.3% 的决策离开蓝图树（超出加注上限，或尺寸转换后 all-in 的手牌继续进行）。
4. **并行**：线程只并行 win 核，4 个线程最多快约 1.6 倍。多个长跑同时进行时互相争用；单进程开 24 个 BLAS 线程会让整机过载（本轮停掉过两次）。
5. **策略不唯一**：比较实现时要看价值、最佳回应和 exploitability，不能直接比较策略。
6. **基线和对局统计功效**：同前。300–1,000 手只能作功能检查。
7. **规则与复现**：同前，见 §4.2 和上一轮记录；续算逐位一致只在同机器、同 BLAS 下成立。
