## 核心操作：输入、动作和可见输出

### 1. Session 与参与者

输入：Session 名称、日期、地点、本地目录、桌人数、SB/BB、ante、straddle、金额显示单位与头像。操作：点击新建 Session，编辑字段、人数与单位，保存进入。输出：独立 Session 和玩家配置。证据：150、165、180、186 秒。可看到 6 人切为 8 人及单位菜单；没有看到其项目文件格式或相对路径恢复算法。

本次对应：创建/保存/打开 Pokerstudio JSON 项目、多个素材、编辑玩家/位置/盲注与金额单位。路径重定位、原文件保护、版本校验和撤销属于为本地使用增加的工程设计。

### 2. 逐街记录手牌

输入：玩家位置/底牌、公共牌、各街行动及下注。操作：记录 straddle、raise、call/fold、发 Turn，选择正在行动玩家。输出：行动序列、桌面牌面、玩家剩余筹码和底池。222 秒显示 Flop `9h Qc 5d` 与底池 1,215；228 秒显示 Turn `Jc`、Hero 下注 1,200 与底池 2,415。后续 fold 后回收未跟注下注，303 秒底池重新为 1,215。记录器是否完整验证所有规则、边池或退款算法没有代码证据。

本次对应：人工可编辑的结构化手牌，未知牌/金额使用 null，时间事件驱动画面；不会从截图推断整手牌数据或将原演示的 8 人局送进两人 solver。首版不是自动桌面识别器。

### 3. 锚点、文稿与录音

输入：手牌行动与人工讲解文本。操作：生成锚点、AI 生成文稿、编辑/选择文稿、开始录音；界面另有上传录音和 AI 配音选项。输出：可编辑讲解、录音状态、后续口播音轨。285、300、345、352 秒分别证明文稿、录音状态、选中文字、口播轨可见。AI 配音按钮标记 token 消耗，只看到选项，未核实该收费服务的账户、模型可用性或独立输出音频。

本次对应：agent 根据已确认手牌/真实 solver 结果起草可编辑讲解，字幕文本/时间编辑、SRT 导入导出。自动配音不在首版必做范围；本地转写接口按实际模型配置工作。不得将订阅身份等同于免费媒体 API。

### 4. 视频剪辑与 SRT

输入：单手素材、人工录音/口播和文稿。352 秒可见三条轨道：视频、原声、口播，及分割、定格、裁剪、分离原声、删除等按钮；视频片段显示 00:00–00:25.52，口播更长。下方有“打开剪映制作”“上传成片与 SRT”，并显示自动查找同名 MP4/SRT 的界面提示。这里确认有内置剪辑视图与外部剪映往返入口；没有逐项实际验证这些按钮的全部行为，也没有看到完整外部剪映工程。

本次对应：直接在本地浏览器预览，按素材秒设置入/出点、切分、重排、删除；使用项目秒统一手牌/字幕/叠加。首版自己导出，支持导入剪映等软件导出的 SRT，不依赖剪映安装、不冒称已完成剪映自动化。

### 5. 完成牌谱与成片

输入：剪辑 MP4、SRT 和结构化手牌。352/354 秒页面描述利用 SRT 中牌码和金额对齐 Hero/公共牌/底池/对手效果，按钮显示正在完成牌谱。358/360 秒实际媒体播放器中有公共牌、Hero 两张底牌、对手未知牌、底池及字幕，公共牌和底池随画面变化。这证明展示的成片包含叠加，不能证明任何文本都能自动匹配或其时间对齐误差为零。

366 秒整场设置可见固定片头、Session 开头、全部手牌、片头/开场背景音乐与手牌背景音乐、生成长篇入口。未实际看到整场生成完成文件；362/405 秒仍有无法读取视频的时长警告。

本次对应：按统一渲染计划实际烧录手牌/行动/底池/说明/字幕，保留原始音轨，CPU H.264/AAC MP4 导出、进度与取消。多素材可把片头/真人开场作为普通片段排序。背景音乐混音、独立口播轨、定格、封面 AI、头像资产管理和自动 SRT 手牌锚点识别尚未实现，不能称为与参考软件逐功能一致。

## 本次完整流程与需求来源

参考视频已确认的主线是：建立 Session → 记录手牌 → 生成锚点/写稿/录音 → 剪辑并得到视频/SRT → 完成动态牌谱 → 排列片头、开场与手牌形成成片。首版采用相同的手牌与叙事驱动思路，直接提供本地剪辑与导出。

用户明确新增的要求：真实 Pokerlab 求解、严格单位/场景检查、订阅与独立 API 双模式可操作 agent、项目保存恢复、取消与错误准确反馈、人工修正未知值、短合成视频验收。这些不从视频推导。

工程设计：Python 本地 HTTP 服务、浏览器界面、非破坏源文件引用、Range 按需读取、缓存/代理、原子 JSON 保存、业务工具共享、异步任务、项目隔离、版本防覆盖、明确 source/global 时间映射。设计可回退，具体数值/算法由代码和实测验收确定。

不能确认的项目：参考软件内部架构/许可、完整音频内容、云服务计费和认证、自动 SRT 识别准确率、整场输出格式/性能、手机同步、所有按钮的交互边界。本项目的实际实现与通过状态以 PROGRESS、README、MEDIA、SOLVER、AGENT 和 ACCEPTANCE 记录为准。
